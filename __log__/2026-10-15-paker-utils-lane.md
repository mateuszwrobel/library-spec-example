Lane U landed: the seven `Infer*` helpers (U1–U6) now live in `src/utils` next to the branding contract, each primitive entry re-exports its own helpers so the spec's import strings compile verbatim, and the actions/adapter sides of ADR-0003 shipped as phantom intersections on the decorated types.

**Branding of the maps, not subtraction of contract members.** The plan's mechanism choice had a trap a structural projection walks into: deriving `InferActions` by subtracting known wrapped members cannot tell an action name apart from a shadowed wrapped member (the actions-lane collision ruling — action names legitimately shadow the copied surface), and any such subtraction list drifts with every API addition. So the brand carries the projection's payload instead: `ActionsBrand<TActions>` sits on `DecoratedValue`/`DecoratedStore` as an intersection alongside the wrapped contract, holding the already-mapped `ActionsSurface<A>`, and `EventsBrand<TEvents>` sits on `DecoratedEvents` holding `EventSurface<E>`. The wrappers keep owning the surface mapping (utils never imports their modules — that would also be a `no-circular` hit since they import `Brand` from utils); utils stays the single reader. Branding the surface rather than the raw map is what makes the U2 witness exactly the spec's map: labels and optional parameters survive via `infer P` tuples, and async actions read `Promise<void>` per A's return rule.

**Phantoms stay type-only, runtime untouched.** All three brands are `unique symbol` phantom properties — zero emitted code. The `Decorated*` edits are intersection additions in the two types files; the factory implementations already return `object` through the overload signatures, so nothing runtime changed. The stacked instance (store+actions+rxjs) carries `Brand`, `ActionsBrand`, and `EventsBrand` side by side and all three read simultaneously — the U6 witnesses on one instance prove the intersection keeps each conditional reader precise.

**Re-export wiring, guard-compatible syntax.** Entries import the helpers `import type` from `@paker/utils` and re-export them with a bare `export type {};` pair — deliberately not `export type {} from "@paker/utils"`: dependency-cruiser's swc parser classifies export-from as a runtime edge and `utils-type-only` fired on all four entries (guard red before the pattern switch). The split form is the already-proven edge kind, so the guard stays green with zero config change.

**TS 7.0.2 adaptation (quoted).** The plan's signature sketch `Parameters<InferActions<T>[K]>` does not compile on the pinned toolchain — `src/utils/index.ts(81,84): error TS2344: Type 'InferActions<T>[K]' does not satisfy the constraint '(...args: any) => any'. Type 'InferActions<T>[keyof InferActions<T>]' is not assignable to type '(...args: any) => any'.` The deferred conditional leaves the indexed access unconstrained at declaration time, so the name-taking helpers use a nested-conditional body (`A[K] extends (...args: infer P) => any ? P : never`) behind the same public signature and the same `K extends keyof InferActions<T>` constraint — U5's compile-failure guarantee lives in the parameter constraint, which is unchanged.

**Verification.** `src/utils/utils.test.ts` witnesses U1–U6 against real composed instances (spec's exact action map with a `forward`-pinned factory, spec's exact event map with a `forward`-pinned factory, computed cell, value through actions+rxjs, store through both wrappers): whole-map `Equals` pins for U2/U4, parameters/result pins for U3, payload pins for U4, identical projections across depths for U6, and entry-vs-utils alias identity legs for the single-owner wiring. U5 pins five live `@ts-expect-error` directives — three constraint failures at helper calls (`"nope"` for parameters/result/payload) and two failing member reads off the projections for `InferActions`/`InferEvents`, which take no name parameter (the resolution for the scenario's "unknown names" leg on those two). The test never imports RxJS operators (ADR-0002 guard): stage placeholders are typed through the adapter's own `EventStage` annotation. The exact-map `Equals` witnesses are themselves the no-RxJS-leakage proof — any operator type in a projection makes the pinned map false.
