Lane S implementation: `store` decomposes an object state into one full value cell per property (`$`-suffixed members) while keeping a coherent whole-state view — `get`/`getInitial`/`set`/`reset`/`subscribe`/hook-call on the store, complete get/set/reset/subscribe/key-ops/hook-call on each cell (S1). Consumed only the published `@paker/value` entry contract plus the type-only `@paker/utils` brand; no sibling internals, no RxJS.

What changed and why: the whole-state view is a maintained snapshot cache, rebuilt on each key change and replaced (never mutated), so `get()` identities stay stable between changes — the store hook (`useSyncExternalStore`) re-renders on any property change while property hooks stay scoped to their key (S5), with no subscribe loop risk. Store-level listeners are a fan-in of one whole-value subscription per cell. That is what pins the exactly-once rules by construction rather than bookkeeping: the value contract delivers one whole-value notification per actual change (deep-path fan-out included, V13–V15), so an external property write — including `setKey` through a path — notifies the store exactly once (S3, S6). Whole-store `set` and `reset` wrap their multi-cell writes in a batch that accumulates cache updates silently and fires one store-level notification with (finalSnapshot, preOperationSnapshot) only when the aggregate identity actually moved — SameValueZero-equal or absent keys stay silent at both levels (S2, S4). `set` iterates the store's own key set and applies only keys present in the patch (`Object.hasOwn`), so partial patches touch nothing else; `getInitial()` returns the construction-time state object itself, kept pristine because every cell write is immutable (S4). Both factory forms mirror `value`: initializer invoked once per instance for SSR/test isolation (S1 witness), plain object shared as the initial reference like `value(obj)`. Tests are test-first per the lane scenarios: `store.test.ts` (S1–S4, S6 counting witnesses per leg, compile-failure `@ts-expect-error` witnesses for out-of-shape names, wrong cell value types, and wrong whole-state reads), `hook.test.tsx` (S5 render-count witnesses), `branding.test.ts` (local conditional-type reader proving `Store<T>` and each `$` cell carry the brand wrapper-transparently; generic inference from both forms). Aliases for `@paker/store` added to tsconfig paths + vitest resolve.alias, mirroring `@paker/value`.

Ambiguities found and resolved (stated, not stalled): (1) The lane brief's "store-level fires EXACTLY ONCE per store-level operation (set/reset/property write)" vs the store workplan decision text "once per property change" — reconciled via the parent's S2 risk mitigation ("per-key subscribers each fire once, whole-store subscriber fires once"): a multi-key `set` is one store-level operation and notifies once with whole before/after aggregates; a single-key write (direct, key-op, deep-path) is one property change = one notification. Both readings coincide on single-key operations; only batching distinguishes them. (2) Store-level `set` argument typed `Partial<T>`: S2's full-replacement witness passes a complete object (assignable to `Partial<T>`), and the parent's A4 rule ("loadUsers returning { data: users } leaves counter$ untouched") needs partial application — one API serves both with per-key firing preserved by the cell-level equality skip. (3) `InferState` re-export from the API table is deferred exactly as the value lane deferred `InferValue`: utils exposes only the `Brand` contract today, so the state-shape witness is the local conditional-type reader; the utils lane adds the re-export line when the helpers land. (4) A function argument is always read as the initializer form (same disambiguation as `value`) — a callable state object is not a spec data class. (5) Reentrant whole-store operations from inside a subscriber during a batched write are not spec'd; the current batch flag would let the outer batch absorb them silently — left unimplemented deliberately (no scope creep), behavior documented nowhere in the plan.
